# LanKVM 验收测试指南

这份文档是给你（和你的组员）照着做的**手工测试清单**。自动化部分我已经跑完（见文末"已自动验证"），剩下的都需要真人坐在两台机器前操作。

按顺序做，每一步都有"预期结果"和"失败怎么办"。**建议边测边在最后一节的表格里打勾记结果**，这些记录直接就是答辩和报告的证据。

---

## 0. 你需要准备什么

| 项目 | 要求 |
|---|---|
| 两台机器 | 都装 Windows 10 1809+（当前开发机是 Win11 26200） |
| 网络 | 同一网段，能互相 ping 通；建议都插网线或连同一个 WiFi |
| 权限 | 两台都用**管理员**身份运行（否则无法向管理员窗口注入输入） |
| 文件 | `lankvm.exe`（3.9 MB，静态链接，不需要装任何运行库） |

网络类型必须是"专用网络"，否则 Windows 会拦入站。在每台机器上以管理员身份运行一次：

```cmd
scripts\setup-firewall.cmd -SetNetworkPrivate
```

（脚本在项目的 `scripts\` 目录，拷到两台机器上都能用；撤销用 `-Undo`。）

## 1. 一次性准备（两台机器各做一遍）

1. 新建目录，例如 `D:\LanKVM\`，把 `lankvm.exe` 放进去。
2. 双击运行一次，它会生成 `D:\LanKVM\lankvm.ini` 并打印预共享密钥（PSK）：

   ```
   first run: config written to D:\LanKVM\lankvm.ini
   pre-shared key: 3f8c...（64 位十六进制）
   ```

3. **把 A 机的这一串 PSK 抄到 B 机的 `lankvm.ini` 里**，两端必须完全一致。
4. **确认该给对端哪个 IP**（有 VMware/WSL 时网卡很多，别靠猜）：

   ```cmd
   D:\LanKVM\lankvm.exe --netinfo
   ```

   它会逐个列出网卡并说明为什么跳过，最后一行就是答案：

   ```
   [6] VMware Network Adapter VMnet8
       ipv4  : 192.168.163.1
       -> skip (virtual adapter: VMware/WSL/Hyper-V/VPN)

   [8] WLAN
       desc  : Realtek RTL8852BE WiFi 6 802.11ax PCIe Adapter
       state : up    gateway: yes
       ipv4  : 192.168.1.3
       -> usable

   best local address: 192.168.1.3
   ```

   规则：**只认标了 `usable` 的那个**，通常是"以太网"或"WLAN"。
   `VMnet1` / `VMnet8` / `vEthernet (WSL)` / `TAP-*` 全部不用。

5. 用设置窗口配角色（推荐，不用手改 ini）：

   - **受控端**：托盘右键 → 设置 → 选"受控端（这台被控制）" → 保存
   - **主控端**：选"主控端" → "对端 IP"填第 4 步的 usable 地址 → 勾"启动时自动连接" → 保存

   保存后程序会按新角色自动重启，托盘提示和标题栏都会跟着变。

6. 也可以命令行指定角色，**程序会把角色写回 ini**，下次双击就是正确角色：

   ```cmd
   lankvm.exe agent
   lankvm.exe master
   ```

> 想改回主控端：设置窗口里选回去，或者 `lankvm.exe master`。

---

## 2. 启动

**先启动受控端**（顺序反了也没关系，主控端每秒重试一次）：

```cmd
D:\LanKVM\lankvm.exe agent
```

再启动主控端：

```cmd
D:\LanKVM\lankvm.exe master
```

两端都会在托盘出现图标（系统默认图标，可能在折叠区 `^` 里）。右键点它能看到菜单。

## 3. 测试用例

### T1 — 启动与托盘（单机，1 分钟）

| 步骤 | 预期 |
|---|---|
| 启动 `lankvm.exe agent` | 控制台打出 `role / config / local / listen` 四行信息；窗口标题是 `LanKVM [受控端] 24800`；托盘出现图标 |
| 鼠标悬停托盘图标 | 提示 `LanKVM [受控端] 192.168.x.x:24800 监听中`（地址与 `--netinfo` 一致） |
| 再启动一次同角色 | 弹窗"已经有一个相同角色的 LanKVM 在运行"，新进程退出，原进程不受影响 |
| 右键托盘 | 弹出菜单：连接/重连、断开连接、设置...、打开日志、关于、退出 |
| 点"设置..." | 顶部有角色单选；选"受控端"时，对端 IP / 边缘方向 / 自动连接三项变灰 |
| 点"关于" | 显示版本、角色、本机地址、配置文件路径 |
| 点"退出" | 进程退出，托盘图标消失 |

**失败**：

- 托盘没图标 → 看 `lankvm.log` 有没有 `cannot create message window`
- 托盘显示的角色和你刚启动的不一致 → 那是**旧实例**。新版本会阻止同角色重复启动，先退出托盘里所有 LanKVM 再试
- 标题栏和 ini 都是 master，但你明明带了 `agent` 参数 → 确认参数没被快捷方式吞掉，或直接用设置窗口选角色

---

### T2 — 双机连接（5 分钟）

| 步骤 | 预期 |
|---|---|
| 两端都启动 | 主控端托盘提示变为 `已连接` |
| 看受控端 `lankvm.log` | 出现 `hello from '<主控机名>' proto=1 caps=0x7` 和 `status: connected to <主控机名>` |
| 看主控端 `lankvm.log` | 出现 `peer screen: 1920x1080 at (0,0) dpi=...` 和 `status: connected to <IP>` |
| 主控端日志等 5 秒 | 出现 `round trip latency: NNNN us`（N 一般是几百到几千） |

**失败**：

- `cannot reach ...` → 防火墙/网络问题，回到第 0 步
- `authentication rejected: invalid key` → 两端 PSK 不一致
- 一直 `cannot reach` 但能 ping 通 → 检查受控端是否真的在监听（`netstat -ano | findstr 24800`）

---

### T3 — 边缘切换 + 鼠标移动（⚠️ 最关键的一条，10 分钟）

这是整个项目风险最高的地方，请**先单独测它**。

| 步骤 | 预期 |
|---|---|
| 1. 主控端把鼠标慢慢推到屏幕**右边缘**，继续往右推 | 主控端的鼠标停住，受控端的鼠标开始动，从它屏幕的**左边缘**出现 |
| 2. 在受控端移动鼠标 | 受控端光标跟手，方向正确（往右推就向右走） |
| 3. 看主控端托盘提示 | 变成 `... / 远程控制中` |
| 4. 主控端日志 | 出现 `status: remote control active` |

**如果光标切过去了但不动**（这是唯一可能导致方案返工的情况）：

说明低层鼠标钩子在拦截事件后，Raw Input 也不再上报位移。请立刻记录现象（截屏 + 日志），告诉我，我会把采集方式改成"钩子内取坐标 + 光标归中"的备用方案——改动只在 `master.cpp` 的采集函数里，不影响其它模块。

**如果完全没切换**：

- 确认 `edge=` 配的是你实际推的那一侧
- 确认 `connected` 为真（T2 必须通过）
- 确认鼠标真的到了屏幕边缘（多显示器时是虚拟桌面的外边界）

---

### T4 — 鼠标按键 / 滚轮 / 拖选（5 分钟）

在受控端打开记事本，全部操作用主控端的鼠标：

| 操作 | 预期 |
|---|---|
| 左键单击 | 受控端光标定位，主控端本地窗口**不应**获得点击 |
| 双击 | 正常双击 |
| 右键 | 出现受控端的右键菜单 |
| 滚轮上下 | 受控端页面滚动 |
| 按住左键拖选文本 | 受控端能选中（拖选过程中不能断） |
| 中键 | 受控端中键行为 |

**失败**：如果主控端本地窗口也被点到了 → 钩子没生效，看日志有没有 `cannot install mouse hook`。

---

### T5 — 键盘（10 分钟）

在受控端打开记事本：

| 操作 | 预期 |
|---|---|
| 输入 `hello world` | 受控端逐字出现，主控端本地无输入 |
| 方向键、Home/End、Delete | 正常（这几个是**扩展键**，最容易出问题） |
| `Shift+字母`、`Ctrl+C/V`、`Alt+Tab` | 组合键正常 |
| 中文输入法打字 | 受控端输入法正常工作，候选框跟着受控端光标 |
| 小键盘数字 | 正常 |

**失败**：方向键变成数字 → 扩展键标志丢了；中文乱码 → 受控端输入法问题，与程序无关。

---

### T6 — 返回本机（2 分钟）

| 步骤 | 预期 |
|---|---|
| 受控端把鼠标推到它屏幕的**左边缘**（即回来的那一侧），继续往左推 | 控制权回到主控端，主控端光标出现在右边缘，位置与离开时大致对应 |
| 托盘提示 | 变回 `已连接`（没有"远程控制中"） |

---

### T7 — 粘键检查（3 分钟，必做）

这是最容易在答辩现场翻车的点。

| 步骤 | 预期 |
|---|---|
| 主控端按住 `Ctrl` 不放 → 鼠标推过边缘进入受控端 → 在受控端按 `C` | 受控端表现为 `Ctrl+C` |
| 保持按住 `Ctrl`，直接把鼠标推回主控端 | 回到本机后，主控端的 `Ctrl` **不应该**一直是按下状态 |
| 另一种方式：按住 `Ctrl` 时直接关掉受控端进程 | 主控端键盘恢复正常，不会"粘住" |

---

### T8 — 断线重连（5 分钟）

| 步骤 | 预期 |
|---|---|
| 连接正常时，直接结束受控端进程 | 主控端 6 秒内检测到（日志 `peer timeout`），托盘变 `等待连接`，光标自动回到本机 |
| 重新启动受控端 | 主控端 1~2 秒内自动重连，日志重新出现 `connected` |
| 连接正常时，拔掉网线 5 秒再插回 | 同上，自动恢复 |

### T9 — 剪贴板：文本双向（5 分钟）

| 步骤 | 预期 |
|---|---|
| 主控端复制一段中文 → 受控端 `Ctrl+V` | 内容一致（含换行） |
| 受控端复制一段中文 → 主控端 `Ctrl+V` | 内容一致 |
| 主控端复制 100 KB 的文本 → 受控端粘贴 | 一致，不卡顿 |
| 连续复制 5 次不同内容 | 每次都能同步，不会来回弹（日志里同一份内容只出现一次 `clipboard sent`） |

### T10 — 剪贴板：图片（5 分钟）

| 步骤 | 预期 |
|---|---|
| 主控端 `Win+Shift+S` 截一块图 → 受控端粘贴到画图 | 图片完整，颜色正确 |
| 受控端截图 → 主控端粘贴 | 同上 |

### T11 — 安全校验（5 分钟）

| 步骤 | 预期 |
|---|---|
| 把受控端 `psk` 改错一位，重启两端 | 受控端日志 `bad pre-shared key`，主控端 `authentication rejected: invalid key`，**连接不上** |
| 改回正确 PSK | 恢复连接 |
| 两端都设 `encrypt_clipboard=1`，抓包（可选，Wireshark 过滤 tcp.port==24800） | 剪贴板内容在流量里**看不到明文** |

| 步骤 | 预期 |

## 5. 故障排查

### 连不上时，先跑这两条命令

在**受控端**：

```cmd
lankvm.exe --netinfo
lankvm.exe --probe <主控端 IP>
```

在**主控端**：

```cmd
lankvm.exe --probe <受控端 IP>
```

`--probe` 会真的发起一次 TCP 连接，并按结果给出结论：

| 输出 | 含义 | 下一步 |
|---|---|---|
| `OK` | 端口开放，网络可达 | 检查两端 PSK 是否一致 |
| `REFUSED` | 主机可达，但没人监听 | 对端 LanKVM 没启动，或端口填错 |
| `TIMEOUT` | 完全没有回应 | 对端关机 / 防火墙丢包 / **两机不在同一网络** |
| `UNREACHABLE` | 路由不可达 | 不在同一网段，换网络 |

**两个方向都要测**：如果主控端测受控端是 `TIMEOUT`，但受控端测主控端是 `REFUSED`，说明受控端能到主控端、反向被挡，基本就是防火墙或网络隔离。

> 校园网/公共 WiFi 常见"客户端隔离"（AP isolation），同一 WiFi 下的两台机器互相不可见。
> 表现就是双向 `TIMEOUT`，但两台都能上网。**换成手机热点或同一台路由器**即可解决。

### 常见现象对照表

| 现象 | 最可能的原因 | 处理 |
|---|---|---|
| 连不上，日志 `cannot reach` | 防火墙 / 不同网段 / 受控端没启动 | 跑 `setup-firewall.cmd`，`ping` 对端，`netstat -ano \| findstr 24800` |
| 主控端日志一直 `connect timed out` | 网络不通或被隔离 | 用 `--probe` 双向测；校园网换热点 |
| 主控端完全没有连接日志 | `auto_connect=0` 且没点"连接" | 设置里勾"启动时自动连接"，或托盘点"连接/重连" |
| 不知道填哪个 IP | 有 VMware / WSL 虚拟网卡 | 跑 `lankvm.exe --netinfo`，只认 `usable` 那一行 |
| 托盘角色和启动参数不一致 | 旧实例没退出 | 新版会拒绝同角色重复启动；先退出所有 LanKVM |
| 改了 ini 但程序没变化 | 程序只在启动时读配置 | 退出重开，或用设置窗口改（保存后自动重启角色） |
| `authentication rejected` | PSK 不一致 | 两端抄同一串 |
| 连上但鼠标不动 | 受控端未以管理员运行 / UIPI | 用管理员启动受控端 |
| 切到远程后光标不动 | Raw Input 被钩子抑制（已知风险） | 记录现象并反馈，改采集方案 |
| 方向键无效 | 扩展键标志丢失 | 记录，修复在 `inject.cpp` |
| 剪贴板不同步 | 源端内容被判定为重复（hash 相同） | 换一段内容再试；看日志有无 `clipboard sent` |
| 剪贴板乱码 | 编码转换问题 | 看日志 `clipboard applied: format=1` |
| 托盘找不到图标 | 被折叠进 `^` 区域 | 点任务栏的 `^` 展开 |
| 文件没到 | 未连接 / 拖到了边缘而不是投递框 | 看受控端日志 `receiving file` |

日志位置：与配置文件同目录，`lankvm.log`。菜单"打开日志"可直接打开。

## 8. 已知限制（写进报告"局限与展望"）

1. 剪贴板只支持**文本和位图**；文件请用投递框（剪贴板文件列表留到 v2）
2. 多显示器按**虚拟桌面外边界**判定，不做逐屏边缘
3. 远程控制时本地光标**停在屏幕边缘**（没有做隐藏）
4. 无法向**管理员权限窗口**注入（Windows UIPI 限制，需受控端提权）
5. 不支持 RDP/平板等**绝对坐标**输入设备（Raw Input 的 `MOUSE_MOVE_ABSOLUTE` 被忽略）
6. 传输**未加密**（只有剪贴板加密）；键鼠事件是明文，仅限可信局域网
7. 文件投递是"拖到投递框"，不是"鼠标带着图标跨屏"（真 OLE 交接在 v2 计划里）
